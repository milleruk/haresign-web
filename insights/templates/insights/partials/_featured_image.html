Both decisions below were previously repeated in all four, which is how three of them end up wrong. **Alt text.** A described image gets its description. An image without one is marked *explicitly decorative* — `alt=""` plus `role="presentation"` — rather than left with an empty alt indistinguishable from somebody having forgotten. Decorative is the right answer here and not a cop-out: every one of these is a designed header card whose visible text is the article's own headline, and in all four render sites that headline is already on the page as text beside it. An alt repeating it would make a screen reader announce the same words twice; describing the artwork would announce decoration as information. Where an image ever carries something the headline does not — a chart with figures in it — `featured_image_alt` is the field for it, and the admin lists which articles have one so the review is possible rather than theoretical. **Format.** `` offers the WebP written by `manage.py optimise_images` and falls back to the original file. WebP alone would be smaller still, but this audience includes locked-down NHS desktops: the fallback costs one element and means a browser that has never heard of WebP gets a resized original rather than a broken image. The `` appears only when the file genuinely exists — see `Article.featured_image_webp_url`. `width`/`height` are deliberately absent: these images vary in aspect ratio and CSS sizes them in every context.
